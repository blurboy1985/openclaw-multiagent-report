What Separates Successful Deployments from Failed Ones

✅ Successful Patterns

  • Start small, scale deliberately (9/12 started with 1-2 agents)
  • Model fallbacks mandatory (8/12 use local Ollama as never-down fallback)
  • Isolated gateways per agent (7/12 learned shared gateways cause cascade failures)
  • Memory writes obsessive (6/12: "no mental notes, write to files")
  • Heartbeat optimization (5/12 switched to cheap/local models, saving 60-90%)

❌ Common Failures

  • Single gateway routing all agents (cascade failures)
  • No local fallback (cloud API timeouts brick operations)
  • Relying on context alone (agents forget on restart)
  • No heartbeat (silent failures, infinite loops)
  • Expensive models for heartbeats ($5/day → $0)

Common "Starter Team" Compositions

Phase 1 (Week 1-2): 2 Agents

1 Orchestrator + 1 Specialist (usually Dev or Research)

Example: Seth → Linus, or Milo → Josh

Multiple machines, department heads, specialized teams

Security Considerations

  • Docker sandboxing for sub-agents (6/12 use Docker isolation)
  • Tailscale for VPS access (3/12 mention private network tunneling)
  • Separate auth profiles per agent (5/12 emphasize credential isolation)
  • 1Password integration (2/12 use 1Password for secure credential access)
  • Read-only production DB access (1/12 explicitly limits sub-agent DB permissions)
  • Limited-scope API keys (4/12 mention using restricted API keys per agent)
